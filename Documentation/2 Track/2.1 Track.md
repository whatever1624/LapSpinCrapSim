The `Track` class defines the track that the vehicle model will drive on

This includes the track surface, track limits and events (timing sectors, DRS, SLM, speed limit zones)



Track class needs to store:
- Surface (which itself encodes the minimum-curvature trajectory)
- Centreline trajectory
- Track limits trajectories
- Cyclic/closed track boolean flag
- Event locations and information (sector lines, DRS, etc.)

Init of a track object either from saved .pkl file, or by passing in:
- Track surface coordinate arrays (track limits, plus optional extras)
	- xyzLimitLeftSoft.csv, xyzLimitRightSoft.csv
	- xyzLimitLeftHard.csv, xyzLimitRightHard.csv
	- xyzSurface___.csv
	- Each row in the files is a coordinate in  `x,y,z` - where going down the row of coordinates is moving forwards along the track
	- ==mostly just copy existing implementation for handling these== - however allow (or enforce?) column headers for consistency with the event trajectory?
	- ==actually change this to make the z coord optional - at least 2 coord arrays with z are required to generate the track, but these don't necessarily have to be the track limit coord arrays==
- Events
	- Provided as a labelled coordinate array trajectory
	- xyzEvents.csv
	- CSV file format, where first 3 columns are `x,y,z`, then subsequent columns are the relevant events:
		- `NSector`
		- `BDRS`
		- `BSLM`
		- `vLimit` (-1 for no speed limit)
- Boolean whether the track is closed (BCyclic)
	- Determines whether to use a periodic spline for the 
- Polynomial degree to use for the z coordinate fitting (default 1?)
- Spatial frequency of the polynomial fitting for the z coordinate (default 0.1?)
	- Actually fit at 10x the frequency, then low-pass filt to this frequency


Init will:
- Create the track surface object
	1. Load all provided coordinate arrays as splines - probably should be Modified Akima splines to avoid overfitting? these splines don't need C2 smoothness so should be fine
	2. Reparameterise the left soft track limits to the right track limit (arbitrary choice really)
	3. Compute the centreline coordinates by interpolating the soft track limit splines - probably use some degree of smoothing for this spline, also needs to be C2 continuous
	4. Reparameterise the soft track limits by centreline distance
	5. Compute the minimum curvature trajectory between the (soft) track limits
	6. Create the surface spine by interpolating the minimum curvature trajectory with a spline - needs to be C2 continuous and compatible with a Modelica 1D table interpolation option
	7. Reparameterise all coordinate arrays by the surface spine
	8. At each longitudinal position along the surface spine, fit a polynomial in the lateral direction to the (interpolated) z coordinate from the coordinate arrays - likely this should be fitting to the cross-track z-gradient plus the average z coordinate
	9. Interpolate the polynomial coefficients with splines - same spline type as the surface spine, for the same reasons
- Create the track limits trajectory objects
	1. Convert the track limit coordinate arrays into the track surface coordinate system
	2. Compute the trajectory angle relative to the track surface spine
- Create the track centreline trajectory object
	1. Average of left and right soft track limits
- Set up event locations and information
